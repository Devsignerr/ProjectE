# 데이터 테이블·RPG 데모·데모 맵

> CLAUDE.md에서 옮긴 상세 규칙이다. 이 영역의 코드·에셋을 고치기 전에 읽는다. 규칙을 바꾸거나 더할 때는 이 문서(또는 관련 머리 주석)를 고치고 CLAUDE.md 요약 줄도 맞춘다.

- 데이터 테이블/에셋(Phase 46): 구조체 `.estruct`(필드 = 이름·타입·기본값, 여러 테이블 공유) + 테이블 `.etable`(구조체 + 순서 있는 행) + 데이터 에셋 `.edata`(값 하나). 형식·읽기 규칙은 `Scene/DataTable.h` 머리 주석, 캐시·검증·핫 리로드는 `Scene/DataLibrary.h`, CSV는 `Scene/DataCsv.h`가 기준. 읽기는 반드시 `FDataLibrary::Get().Load*`(FFileSystem, 경로 캐시, 세대) — `shared_ptr`을 오래 드는 코드는 `GetGeneration()`이 바뀌면 다시 Load. 파일을 고치는 코드는 `FDataLibrary::Save*`(쓰고 Invalidate), 구조체 변경은 `SaveStructAndMigrate`(필드 이름 변경 목록 `{From,To}` → 사용 파일 함께 `Rebind`). 필드 이름은 식별자, `Name`은 예약어. 값 형식(`FDataValue`)이나 JSON/CSV 표기를 바꾸면 `FDataStruct/FDataTable/FDataAsset::Version`과 `DataTableTests`. Lua `Data.*` 결과는 매 호출 새 테이블(큰 표는 OnStart에서 한 번 받고 `Data.GetGeneration()`이 바뀌면 다시). 중첩 구조체 미지원 — RowRef로 정규화. 엔진 DLL 내보내기 여유가 약 4천 개이므로 큰 템플릿 인스턴스를 늘리는 변경은 `.def` 개수를 확인한다

- RPG 수치(Phase 46-C): `Data/RPG/*` — 아이템 `Items.etable`(행 이름 = 아이템 id, 저장 파일 호환), 전리품 `LootTables.etable` + `LootEntries.etable`(파일 순서로 굴림), 적 `Enemies.etable`(필드 이름 = EnemyController Properties + MaxHealth, 프리팹은 `StatsRow`만), 플레이어 `PlayerBalance.edata`(PlayerController `BalanceAsset`), 새 게임 `GameBalance.edata`, 상점 `Shops.etable`(Merchant `ShopRow`). 스크립트는 `Script.Require("Scripts/RPG/RPGData.lua")`로만 읽는다(세대별 캐시, 받은 테이블은 고치지 않음). 행/에셋 값이 같은 이름의 프로퍼티보다 우선, 없으면 프로퍼티 값. 적·플레이어 스탯은 OnStart에 한 번. 새 수치는 스크립트 상수 대신 구조체 필드로 추가한다

- RPG 데모(Phase 45, Tests/PixelArt): 트랙 간 계약 = `GameManager` 엔티티 스크립트(`Scripts/RPG/GameManager.lua` — 아이템·전리품 표 `Items`/`LootTables`, 가방/장비/골드/알림/`SpawnLoot`/`ShowDamageNumber`/`TrackEnemy`) + `Player`(`PlayerController.lua`, `IsPlayer`, `GetStats/GetSkillCooldowns/EquipWeapon/EquipShield(def|nil)/RestoreHealth/RestoreMana/Respawn`) + 적(`EnemyController.lua`, `IsEnemy`, `GetDisplayName/IsDead/GetHealthFraction`). 다른 스크립트는 `Scene.Find(이름):GetScript()`로 쓰고 nil이면 건너뛴다. 타격 시점 = 모델 `.emeta` 노티파이(기사 AttackHit/SpinHit, 스켈레톤 Hit/Shoot/Cast) — 클립·배속을 바꾸면 스크립트 표와 함께. 플레이어 몸 방향은 PlayerMesh 로컬 회전(Standalone은 소유자 없는 캐릭터에 ControlYaw 미적용), 블렌드 위치는 클립 발 속도(기사 Running_A 345, 스켈레톤 75/240/450). 적은 Lua 상태 머신 + `entity:MoveTo`, 루트 키네마틱 캡슐 + 레이어 `Enemy`. 머리 위 체력바/데미지 숫자는 HUD(`HUDController` 오버레이, `UI/RPG/HUD.eui`의 숨긴 템플릿 복제). 적이 있는 씬은 `NavMeshComponent` + 에디터 `--bake-navmesh` 후 씬 JSON에 `.enav` 경로. 효과음은 WAV/FLAC/MP3(miniaudio 빌드에 Vorbis 없음 — ogg 불가). 아이콘은 `Asset/Icons/7Soul_RPG_Icons/`(4배 확대 PNG — UI 샘플러가 선형)

- 데모 맵(`Scenes/Demo/`): Hub(해안 항구, 기본 맵) + 포털로 가는 기능별 서브맵(`Scenes/Demo/<이름>.escene`, Hub 포털 `Ready`로 연결 — 새 서브맵은 Hub `READY_PORTALS`에 이름을 넣어 포털을 연다). **씬 파일을 직접 고치지 말고 생성 스크립트(`Tools/DemoMap/Build*.py`, numpy)를 고쳐 다시 만든다** — 지형·머티리얼·플레이어 프리팹도 생성물. 실사 에셋은 Poly Haven(CC0) 원본을 저장소에 넣지 않고 `Scripts/FetchDemoAssets.ps1`(+`-Update` = 잠금 파일 `Scripts/DemoAssets.json` 갱신, MD5 고정)로 `Asset/PolyHaven/`에 받는다(.eimport만 커밋 — 잎이 BLEND인 에셋은 `BlendAsMasked`, 스캔 에셋은 `.eimport` `MaxTriangles`로 쿠킹 때 줄인다 — 마스크 잎 메시는 `MeshSimplifier` 잎 솎아내기). 스캔 에셋은 수십만~수백만 삼각형이라 같은 메시를 재사용하고 새 에셋은 `polycount`를 먼저 본다. 플레이어 `Prefabs/Demo/DemoPlayer.eprefab`(UAL2 마네킹 + KayKit 이동 클립 리타기팅, V = 3인칭/1인칭/탑뷰), 포털 `Scripts/Demo/DemoPortal.lua`(`Game.OpenScene`). 검증 기준 씬은 `Scenes/Tests/`(데모용으로 고치지 않는다)
  - 공통 기법: 상자 건축면(벽/바닥/천장)은 `Materials/Demo/Lighting/TiledPBR.emat`(내장 큐브 UV × Tiling 그래프) 인스턴스로 면 크기별 타일을 맞춘다. 반사 캡처는 굽기가 DDGI 없이 하늘빛만 담아 실내에 푸른 반사가 얹히므로 DDGI 실내 데모에 두지 않는다. 모듈 키트(파사드 등 — 조각이 한 파일에 흩어짐)는 `Tools/DemoMap/GltfKit.py`로 고른 조각만 놓은 조립 glTF(`Asset/DemoKits/`, 원본 .bin/텍스처를 상대 경로 참조, 커밋)를 만들고, 내장 큐브 바닥·벽은 월드 좌표 UV 그래프 머티리얼로 텍스처 밀도를 맞춘다. Poly Haven 액자 유리(BLEND)는 알파 없는 jpg를 써서 불투명해지므로 유리만 고친 glTF 사본(`Asset/Gallery/`, 공용 `Tools/DemoMap/AssetFixes.py` `FrameModel` — Lighting도 같은 사본)을 쓴다. 코브 조명은 칸마다 나눈 면광원(긴 면광원 문 덮개 문제는 2026-10-04 엔진에서 고침 — 이제 한 줄로도 같다). 잎 카드 알파가 별도 맵인 에셋은 잠금 파일 `AlphaMaps`로 받아 FetchDemoAssets가 `<Id>_<접두사>_diffalpha_2k.png`로 합치고(JPG 색에는 알파 없음, 재질별이 아닌 단일 맵은 접두사 `*` → `<Id>_diffalpha_2k.png`), 원본 파일 그대로 놓는 맵(Hub)은 `AssetFixes.WriteAlphaFixedModel`이 쓴 사본 `<Id>.alpha.gltf`(커밋)를 쓴다(잎이 실제 기하인 에셋은 제외 — 마스크로 잘림). 한 파일에 변형이 나란히 놓인 에셋은 생성 스크립트가 변형별 `<Id>_<변형>[_leaves<단계>].part.gltf`(커밋, 잎은 따로 나눠 상한)로 나눈다. 개울·웅덩이처럼 굽은 물은 지형 전체를 덮는 물 상자 하나 + 파낸 바닥으로 만든다(여러 상자는 굽이에서 겹치거나 틈이 보인다). glTF `alphaMode: BLEND`인데 알파가 없는(알파 없는 JPG, 색 알파 1) **불투명 물체**는 생성 스크립트 `IMPORT_SETTINGS`에 `BlendAsMasked`를 준다 — 반투명으로 그려지면 사전 패스·움직임 벡터·그림자·SSAO가 빠지고 TAA 반응형이라 지터로 떤다(2026-10-05 Workshop `plastic_crate_02`). 램프·가로등 유리처럼 광원을 감싸는 BLEND 유리는 그대로 둔다(불투명/마스크면 그림자로 빛을 막음)
  - Lighting: 선술집 홀 — `BuildLighting.py`
  - Alley: `BuildAlley.py`, 가운데 배수로 바닥은 어둡고 거친 콘크리트(밝은 젖은 콘크리트가 높은 시점에서 하늘을 비춰 회색 띠로 떴다)
  - Gallery: 조각 전시 홀·머티리얼 — `BuildGallery.py`
  - Forest: 개울 흐르는 전나무 골짜기 — `BuildForest.py`
  - Campfire: 해 질 녘 해변 캠프·파티클 — `BuildCampfire.py`, 파티클은 생성 스크립트가 .eparticle v2로 쓰고 신호 조명탄은 `CampfireFlare.lua`가 파티클 Asset을 비웠다 다시 넣어 재시작
  - Workshop: 물리 창고 — `BuildWorkshop.py`. 실제 메시 동적 바디(콜라이더는 모델 로컬 근사, 받침 면에 정확히 닿게 놓아 시작 때 튀지 않게)와 관절·트리거·래그돌 연출은 `Scripts/Demo/Workshop/*.lua`(보이지 않는 관절 밧줄은 `WorkshopRope.lua`가 캡슐로 그린다). 넘어져야 하는 물체(도미노 선반)는 `RollingResistance` 0 — 닿아 있는 동안 회전을 줄여 사슬이 끊긴다
  - Training: 요새 안뜰 훈련장·애니메이션/AI — `BuildTraining.py`. 내비메시는 생성 뒤 에디터 `--scene Scenes/Demo/Training.escene --bake-navmesh`로 다시 굽고 `.enav` 커밋, UAL2 마네킹 무기 소켓·노티파이는 스크립트가 `UAL2_Standard.glb.emeta`에 쓴다. 소켓 부착 무기를 모델 엔티티의 자식으로 두면 모델 노드 계층이 만들어지지 않는다 — 형제/루트 아래에
  - HD2D: HD-2D풍 마을·들판(도트 스프라이트 캐릭터 + 3D 디오라마) — `BuildHD2D.py`, 도트 아트는 절차 생성 `HD2DArt.py`(1 도트 = 6cm, 캐릭터 피벗 = 발, 옆모습은 오른쪽 — 왼쪽은 반전). 카메라는 +Y 쪽에서 -Y를 보는 고정 원근(시야각 24, 피치 -28)이라 스프라이트는 회전 없이 XZ 평면에 선다 — 큰 건물·산은 안쪽(-Y), 카메라 쪽(+Y)엔 낮은 물체만. 캐릭터 스프라이트는 Masked + 조명 + 그림자, 3D 캐릭터 이동기가 루트를 이동 방향으로 돌리므로 스프라이트는 `Visual` 자식 아래 두고 스크립트가 OnLateUpdate에서 루트 회전을 상쇄한다. 게임 로직 `Scripts/Demo/HD2D/*.lua`(대시 = `AddKnockback`, 공격 판정 = 관리자 슬라임 목록 거리, 효과는 스크립트 없는 `FxSprite` 프리팹 조각). KayKit 마을 키트는 배율 4.5, 앞(문) = 엔진 -X → Yaw -90이 카메라 쪽. 자동 검증: `python Tools/DemoMap/BuildHD2D.py --views`(커밋하지 않는 `_HD2D*.escene` 변형) 후 `.\Scripts\Verify.ps1 -Target Runtime -Config Release -Frames 2700 -ExtraArgs "--scene Scenes/Demo/_HD2DAutoPlay.escene --fixed-delta 60"` → 로그 `[HD2D] 결과: 실패 0건`
