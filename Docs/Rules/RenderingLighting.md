# 렌더링 조명 (RT·DDGI·RTAO·면광원·하늘·로컬 라이트·그림자 캐시)

> CLAUDE.md에서 옮긴 상세 규칙이다. 이 영역의 코드·에셋을 고치기 전에 읽는다. 규칙을 바꾸거나 더할 때는 이 문서(또는 관련 머리 주석)를 고치고 CLAUDE.md 요약 줄도 맞춘다.

- 레이 트레이싱(Phase 50, DXR 1.1 인라인 RayQuery SM 6.5 — 상태 객체 미사용, PSO 캐시·렌더 그래프 그대로): 가속 구조는 `FRayTracingScene`(Renderer/RayTracingScene.h 머리 주석이 기준)만 만든다(입력 = 프레임 `FMeshInstanceList` + 지형 타일 + 스킨 계산 스키닝 refit). **새 메시 종류를 RT에 넣으려면** `Prepare`에 FVertex(64B) 정점 + uint32 인덱스로 BLAS 항목을 만들고 인스턴스 정보(바인드리스 힙 칸 VB/IB, FirstIndex, 머티리얼 표 번호, `InstanceInfo*` 플래그), 마스크 `GetInstanceMask`(종류 + 그림자 캐스터), 플래그 `ComputeInstanceFlags`(Masked = FORCE_NON_OPAQUE), 히트 그룹 오프셋 `ComputeHitGroupOffset`을 채운다. 빌드는 프레임 상한 32·압축, 해제는 지연. **스킨 메시는 모델(스켈레톤 `FSkinComponent::Joints[0]` + 양면·그림자 비트) 하나 = BLAS 하나, 프리미티브마다 지오메트리**(지오메트리별 OPAQUE 플래그 — Masked만 후보)이고 정점·BLAS는 풀 버퍼 2개에 하위 할당(`RayTracingMath::FRangeAllocator`, 그래프 리소스는 엔티티 수와 무관하게 2개) — 히트 정보 번호는 **`InstanceID + GeometryIndex`**, 정점은 `FRayTracingInstanceGpu::BaseVertex`를 더해 읽는다(새 히트/후보 코드도 같은 식). 먼 스킨 모델은 `r.RayTracing.Skinned.RefitDistance`(1500cm) 밖이면 거리에 따라 2~`RefitInterval`(4) 프레임마다 엇갈려 갱신(그 프레임은 스키닝도 건너뜀, 식 `GetSkinnedRefitInterval/ShouldRefitSkinned` — 프레임 번호만의 함수), `Skinned.MaxDistance`(5000cm) 밖은 TLAS 제외. 스크래치는 슬롯당 약 32MB 예산을 넘으면 처음부터 재사용(`FBuildOp::bScratchBarrier`). 엔티티마다 그래프 리소스를 가져오지 말 것(`FindImported` 선형 — 3600개에서 CPU 20ms+) 렌더 그래프에서 AS는 `ImportAccelerationStructure` + `ERGAccess::AccelStructRead/Write`(전이 없음, 쓰기가 끼면 UAV 배리어). 추적 패스는 `FRayTracingPassRoot` + 전체 화면 **픽셀** 셰이더(머티리얼/IBL 텍스처가 항상 PIXEL_SHADER_RESOURCE이기 때문 — 계산 셰이더로 하려면 텍스처 상태 규칙 전체를 바꿔야 함) + `DeclareTraceReads(Pass, Tlas)`. 머티리얼 히트는 `RayTracingCommon.hlsli` `EvaluateHitMaterial`(고정 PBR = `MaterialDefault.hlsli` `E_MATERIAL_CUSTOM_RESOURCES` 분기, 그래프 = 씬 TLAS의 그래프 셰이더를 해시 순 슬롯 `RtGraphMaterialN`으로 이어 붙인 변형 — `GetGraphVariant()`, 디파인 `E_RT_GRAPH_MATERIALS`, 실패하면 회색 근사), 바인드리스 = 셰이더 가시 힙 전체를 공간 1 `Texture2D[]`/공간 2 `ByteAddressBuffer[]`로, 머티리얼 표(80B)는 매 프레임 `Prepare`가 다시 채운다(밉 스트리밍 교체 대응). 히트 텍스처 밉은 광선 원뿔 LOD이며 **스트리밍 필요 밉을 보고하지 않는다**. 히트 조명 `RayTracingLighting.hlsli`(방향광 = `PerFrame.DirectionalLight` + RT 그림자 광선, 로컬 라이트 앞 16개 그림자 없음, IBL은 `FIblRenderer::GetLightingTable()`, 발광), 반사 히트 색에 안개/공중 원근은 아직 미적용(후속 — 히트 거리 기준). RT 반사는 SSR과 같은 출력을 내고 `FScreenSpaceReflections::AddResolvePasses`(결정적 원판 흐림 + 반사 움직임 누적, 거칠기 한계 0.6)를 재사용, RT 그림자 = Bayer 4x4 교차 + 태양 원반 Vogel 표본 → 깊이·법선 공간 필터 → 시간 누적 → 메시 t24(`PerFrame.RayTracedShadows`, 반투명·볼류메트릭 안개는 섀도맵). 반투명·물은 TLAS 밖. 효과가 꺼진 화면은 래스터와 비트 동일(`--no-raytracing`). 식(`RayTracingMath.h` ↔ hlsl)을 바꾸면 `RayTracing_*`. 기본: 프로젝트 설정 Rendering RT 반사 켬, RT 그림자 끔(1440p +1.3~1.8ms). 확인 `--debug-view rt-reflections|rt-shadows|rt-instances`(r.DebugView 7/8/9, 내부 해상도 100%일 때만), `r.RayTracing.DebugMode 1|2`, `r.RayTracing.Stats`, `--raytracing/--no-raytracing/--rt-shadows/--rt-reflections`. **DDGI(Phase 51)용**: `FRayTracingScene::GetTlasAddress/GetInstanceBuffer/GetMaterialBuffer/GetGraphParamBuffer`, 그래프 키 `AddBuildPasses`가 TLAS 참조를 돌려줌, 셰이더 `TraceClosestHit(Ray, E_RT_MASK_TYPES)`/`LoadHitSurface(Hit, 원뿔 폭, -Dir)`/`EvaluateHitLighting(Surface, View)`/`SampleSkyRadiance(Dir, 거칠기)`/`TraceOcclusion`, 디스패치 = `FRayTracingEffects::AddReflectionTracePass` 패턴(`SelectPipelines` → `BindRoot` → 타깃에 전체 화면 그리기 — 프로브 광선도 "프로브×광선" 2D 타깃에 픽셀 셰이더로) **지연 초기화(2026-10-05)**: `FRayTracingScene::Init`·`FRayTracingEffects::InitRayTracing`·`FDdgiRenderer::InitRayTracing`(가속 구조 버퍼·RT/DDGI 셰이더·루트 시그니처)은 RT 효과(그림자/반사/디버그/DDGI)가 처음 필요한 프레임에 `FSceneRenderer::EnsureRayTracing`(BeginRender, PSO도 지연)이 만든다 — RT를 끈 프로젝트(2D)·미리보기·썸네일은 만들지 않는다. Init 때는 메인 패스가 늘 묶는 1x1 RT 그림자 마스크·DDGI 기본 아틀라스만. 켜짐 판정 전 지원 여부는 `IsRayTracingAvailable()`(초기화 전 = DXR 1.1 지원), 실패하면 그 실행은 래스터만

- 동적 GI DDGI(Phase 51, `Renderer/DdgiRenderer.h` 머리 주석이 기준): 볼륨 = `FIrradianceVolumeComponent`(Scene/IrradianceVolume.h) — 상자를 칸으로 나눠 칸 가운데에 프로브, 상자 = 셰이딩·페이드 범위라 **방·건물보다 조금 크게** 잡아 바깥에도 프로브 층을 둔다(축 2~32, 볼륨 8192, 전체 16384, 볼륨 8개). 식은 `Renderer/DdgiMath.h` ↔ `DdgiCommon.hlsli`/`DdgiBlend.hlsl`/`DdgiTrace.hlsl`(바꾸면 `Ddgi_*`). 아틀라스: 조도 10x10 타일(E/π, 옥타헤드럴 8x8 + 테두리), 거리 18x18 타일(1.5×|간격| 정규화, 체비셰프 가시성), 상태 텍셀(w = 상태 + 4×갱신 횟수, 재배치 오프셋·벽 속 비활성), 이력 2장 전용 `FRGResourcePool` UAV(평소 SrvPixel). 프레임 순서: TLAS 뒤·사전 패스 전에 `Prepare` → `ImportFrame` → `AddUpdatePasses`(추적 = RT 루트 픽셀 셰이더 "광선×프로브", 누적 = 계산 셰이더 그룹/프로브, 예산 `r.DDGI.ProbeBudget` 1024). 메시·지형 루트는 b9 + t40~t42(메시 #27~30, 지형은 LightTextures 뒤) — **새 메시 패스는 이 바인딩과 `Ddgi.DeclareShadingReads`를 함께**. 볼륨이 없으면 `EvaluateImageBasedLightingEx`는 예전 식 그대로(비교 `--no-raytracing` Materials/Decals MD5). 히트 간접 확산 훅 `E_RT_HIT_DIFFUSE_IRRADIANCE`(정의 안 하면 원래 식과 토큰 동일, 볼륨 안 프로브 값 없으면 0, 볼륨 밖은 하늘) = 다중 반사. 히스테리시스: 처음 n번 누적 평균 → 0.97, 조명 변화(방향광 2도·10%, 하늘 10%) 30프레임 가속(0.7). **텍셀 급변 감지(`r.DDGI.ChangeThreshold`)는 기본 끔(1.0)** — 광선 잡음에 걸려 프로브 단위로 깜빡였다(2026-10-04 사용자 보고 "Tests/GI 깜빡임"). 조명 변화는 CPU 결정적 감지 가속(`LightChangeBoostFrames`/`LightChangeHysteresis`)만 쓴다. 재배치는 `DdgiMath::ComputeRelocationOffset` ↔ `CSProbeData` 같은 식, 되돌아가는 문턱 = 미는 문턱 × `RelocationReturnScale`(2) — 같으면 벽 옆 프로브가 매 프레임 왕복해 깜빡였다(`Ddgi_RelocationConvergesWithoutOscillation`). **조도 아틀라스는 RGBA32F** — 16비트는 히스테리시스 걸음이 반올림에 먹혀 어둡게 치우친다(h 0.99에서 −6%), 누적 이력을 반정밀도로 두지 않는다. 히스테리시스는 `ComputeFrameHysteresis`: 가속(0.7, 30프레임) → 정착(`r.DDGI.SettleFrames` 300 / `SettleHysteresis` 0.97) → 볼륨 값. 광선 잡음 std ∝ √((1-h)/(1+h)/광선 수)이고 회전 수열을 바꿔도 줄지 않으므로 실내 볼륨은 Hysteresis 0.99·광선 512(Tests/GI). RT 미지원·미리보기·캡처 굽기·픽셀 아트는 꺼짐. CVar `r.DDGI`(`--no-ddgi`), `r.DDGI.ProbeBudget`(`--ddgi-budget`), `BounceIntensity`, `ChangeThreshold`, `MaxLocalLights`, `ShowProbes`(`--ddgi-probes`), `LightChangeBoostFrames/Hysteresis`. 확인 `--debug-view gi`(r.DebugView 10), `r.DDGI.Stats`. 데모 `Scenes/Tests/GI.escene`(G 키 해 방향), Tests/Apartment `BuildingGI`. RT 자동 검증 결정성: 로드 방식이 Async가 아니면(자동 검증 비우기·동기) BLAS 빌드 상한 없음 — 같은 프레임에 모두 빌드

- RT 앰비언트 오클루전(RTAO, 2026-10-04 사용자 보고 "실내 그림자 품질 형편없음"): 원인은 직접광 그림자(캐스케이드는 RT 그림자와 거의 같음)가 아니라 **간접광만 받는 곳의 가림 부재**였다 — DDGI 프로브(100cm)는 물체 크기 가림을 못 담고 SSAO는 거의 보이지 않았다. `FRayTracingEffects::AddAmbientOcclusionPasses` + `RayTracedAmbientOcclusion.hlsl`: 반해상도 추적(픽셀당 코사인 광선 2개, Bayer 4x4 교차 표본, 가림 = (1 − t/반경)², 기본 반경 150cm = 프로브 간격 × 1.5) → 5x5 텐트 공간 필터(주기 4 패턴 칸마다 가중 합 1 — 결정적) → 시간 누적(0.1). 결과는 SSAO와 같은 형식(R 가시도, G 뷰 깊이 cm)이라 메인 패스 t16·지형이 그대로 읽고 간접광에만 곱한다. `r.RayTracing.AO` -1 = DDGI 볼륨이 활성인 프레임만(0 SSAO, 1 항상, `--rtao`/`--no-rtao`), 식은 `RayTracingMath` RTAO ↔ hlsl(`RayTracing_AmbientOcclusionSampling`). 반경·지수·해상도는 **경로 추적 기준 `r.RayTracing.AO.Reference N`(`--rtao-reference`, 4번 반사·그림자 광선·마지막 정점만 DDGI, 정지 카메라)과 `--debug-view gi` rmse로 정한다**(Tests/GI 8시점: DDGI만 14.4, SSAO 11.8, RTAO 10.2) — 기준을 "한 번 반사 + 히트 DDGI"로 만들지 말 것(가림 과소평가). 반해상도 추적을 씬 해상도로 업샘플하면 정지 화면 표준편차가 커졌다. 1440p 0.63ms(SSAO 0.59). `FRayTracingPassRoot` b2(`Root_Extra`) = 패스별 추가 상수. 데모 `Scenes/Tests/GI.escene`(그림자 유형별 구조, 숫자 키 1~8/Tab 시점 `Scripts/GiViewCycle.lua`). 알려진 것: DDGI는 경로 추적 대비 간접 확산이 화면 평균 +7~16/255 과대(프로브 보간), RT·DDGI 없는 씬은 여전히 약한 SSAO

- 면광원/IES/쿠키(Phase 52): 식과 규칙은 `Renderer/AreaLightMath.h` 머리 주석이 기준이고 `AreaLight.hlsli`·`Lighting.hlsli`와 **같은 식**(바꾸면 `AreaLight_*`/`Ies_*`/`LightCookie_*`). `FAreaLightComponent`(Shape Rect/Disc — 끝에만 추가): 빛 = 로컬 +X, 폭 = Y, 높이 = Z, 스케일 무시. Intensity = 면 법선 1m 조도(점광원과 같은 단위), 휘도 = Intensity × 1e4 / 면적(렌더러가 Color에 미리 곱함). LTC는 ltc_code 표 2장(`LtcTables.cpp`, BSD — `LtcTables.LICENSE.txt`), 지평선은 구 근사 표(.w), 원판은 같은 넓이 8각형. 감쇠 창 = 면 최근접 거리, 문 덮개 원뿔도 면 최근접 점 → 표면 방향(`ComputeBarnDoorCos` ↔ `AreaLightBarnDoorCos`, RT 히트·안개 대표점 근사도 — 가운데 기준이면 긴 면 끝이 원뿔 밖으로 잘려 27m 코브 조명이 가운데 한 점만 밝았다), 클러스터 경계 = `LocalLightBoundingRadius`. `FLocalLightGpuData` 128B(앞 64B는 Phase 23 그대로)·`FClusterConstants` 176B는 뒤에만 덧붙인다. 면광원 그림자 = 스포트식 1장(반각 = 문 덮개 각, 최대 80°) + 고정 Vogel PCSS(가림 탐색·PCF 각 **64탭** — 16탭은 넓은 반그림자에서 텍셀 계단 얼룩, 탭 수를 바꾸면 256탭 기준과 구석 크롭 비교) + 수신 평면 기울기 바이어스(픽셀마다 흔드는 표본 금지). IES는 `FIesProfile`(LM-63 전 버전)을 `FFileSystem`으로 읽어 θ64×φ32 R32F로 굽는다(0° = Forward, φ 0 = Right, 핫 리로드 없음). 쿠키는 공개 `LoadTexture`(고정): 스포트/면광원 원근, 점광원 위도-경도, 방향광 수직 평면. LTC·IES·쿠키는 셰이더 가시 힙 칸 번호로 넘기고 메시·지형 루트의 **공간 3 무제한 표**(메시 #26 `RootParam_LightTextures`)로 읽는다 — **새 메시 패스·루트 시그니처도 이 표를 묶는다**. RT 히트·볼류메트릭 안개는 대표점 근사(`AreaLightApproxAttenuation`, 안개는 IES/쿠키 없음). 면광원·IES·쿠키가 없는 씬은 비트 동일. 데모 `Scenes/Tests/AreaLights.escene`(발광 패널 메시는 광원 가운데보다 6cm 이상 뒤 — 그림자 근평면 5cm)

- 방향광 그림자 캐시/LOD/컬링(2026-10-04, 규칙 기준 `Renderer/ShadowCacheMath.h` 머리 주석, 테스트 `ShadowCache_*`): 캐스케이드마다 정적 캐스터만 그린 캐시(`CascadedShadowCache`, 평소 COPY_SOURCE, 그래프 Import)를 두고 키(캐스케이드 뷰-투영 비트·해상도·바이어스·LOD 바이어스·작은 캐스터 문턱·정적 집합 해시(LOD 제외)·추가 캐스터 상태 해시·캐시 세대)가 지난 프레임과 같으면 Rebuild → 이후 Reuse(캐시 → 섀도우 맵 복사 + 동적만, 동적이 없고 섀도우 맵 장이 이미 같은 캐시 내용이면 복사도 생략), 키가 바뀐 프레임은 Direct(예전과 같음 — 태양이 움직이는 시간대 애니메이션은 비용 그대로). 정적 = 비스킨 + 월드 행렬이 `r.Shadow.Cache.StaticFrames`(30) 프레임 비트 동일(`FMeshInstance::bShadowStatic`, 씬 렌더러 `ApplyMotionHistory`), 폴리지는 항상 정적, 지형은 `FShadowRenderer::ExtraCasterState`(= `FTerrainRenderer::GetShadowStateHash`). **새 그림자 캐스터 종류는 정적/동적을 알린다**(`AddExternal`이면 `bShadowStatic`, 추가 캐스터 훅이면 상태 해시 — 알리지 않으면 동적 = 매 프레임). 해시에 담기지 않는 변경(같은 핸들 다시 로드 등)은 `FShadowRenderer::InvalidateCache()`(셰이더 다시 로드는 자동). 그림자 LOD = 메인 LOD + floor(캐스케이드 × `r.Shadow.LodBias`)(기본 0 — 0.5에서 Hub 나무 그림자 모양이 눈에 띄게 바뀜, `bFixedLod` 제외, 스킨 포함, 깊이 묶음 키의 LOD로 그림 — `FInstanceBatch::Key`), 작은 캐스터 `r.Shadow.MinCasterTexels`(1: 경계 구 지름 < 캐스케이드 텍셀 1개면 그 캐스케이드에서 뺌). 메인·깊이 사전 패스는 `PrepareMainBatches`에서 `r.MinScreenSize`(0.002)/`r.MaxDrawDistance`(0 = 끔)로 거른다(같은 묶음이라 두 패스 집합 일치 — 그림자·RT는 자기 기준). **이동 중 재사용**: 캐스케이드 `r.Shadow.Cache.QuantizeFirstCascade`(1)부터 `ShadowMath::ComputeCascade(…, Quantize)`가 반경을 (1 + `r.Shadow.Cache.Quantize`(0.125))배로 넓히고 중심을 광원 공간 XYZ 칸(텍셀 배수, G/2 ≤ Quantize × 반경)에 반올림 → 칸 안에서는 뷰-투영 비트 동일, 칸을 넘으면 직전 캐시를 2프레임 이상 재사용했을 때 그 프레임에 바로 Rebuild(`ImmediateRebuildReuseFrames`). 칸이 텍셀 배수라 넘을 때 텍셀 격자가 그대로(가장자리 튐 없음). 캐시 키에는 메인 LOD·지형 청크 LOD를 넣지 않는다(캐시는 다시 그린 시점 LOD — LOD 설정 변경은 씬 렌더러가 무효화).
