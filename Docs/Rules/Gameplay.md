# 게임플레이·물리·캐릭터·입력·AI

> CLAUDE.md에서 옮긴 상세 규칙이다. 이 영역의 코드·에셋을 고치기 전에 읽는다. 규칙을 바꾸거나 더할 때는 이 문서(또는 관련 머리 주석)를 고치고 CLAUDE.md 요약 줄도 맞춘다.

- 물리(Jolt 5.6): 엔진 cm ↔ Jolt m 변환은 `FPhysicsWorld` 경계에서만. 축·쿼터니언 성분은 그대로 넘긴다(엔진 FQuat도 해밀턴 곱/q v q* — `PhysicsTests`가 Jolt와 비교 검증), 중력만 -Z. 컴포넌트는 `RigidBody`/`Box|Sphere|CapsuleCollider`(Physics 모듈 `RegisterPhysicsTypes()`, 씬 로드 전 호출), 바디 핸들은 `FPhysicsSystem`이 엔티티별로 보관(컴포넌트에 런타임 상태 없음). 질량은 `Mass`>0이면 직접 지정, 0(기본)이면 콜라이더 부피 × `Density`. 구르기 저항(`RollingResistance`)은 Jolt에 없어 `FPhysicsWorld::Step`이 접촉 리스너로 이번 스텝에 닿은 동적 바디의 회전만 줄인다. 순서: 스크립트 → `FPhysicsSystem::Update`(60Hz 고정 스텝 + 보간 결과를 트랜스폼에 씀) → `UpdateTransforms`. 에디터는 플레이 중에만 시뮬레이션(`FPlayMode`가 Begin/Update/End). 스크립트가 만든 엔티티의 바디는 다음 물리 갱신에 생기므로 힘/충격량은 그 다음 프레임부터. Lua: `entity:AddForce/AddImpulse/SetVelocity/GetVelocity/GetMass`(충격량 계산은 컴포넌트 `Mass` 대신 `GetMass()`), `Physics.Raycast` (Scripting은 `FScriptPhysicsHooks`로 Physics에 비의존)

- 충돌 알림/관절/래그돌(Phase 30): 콜라이더 `bIsTrigger`, 강체 `bReportContacts`. 보고 대상 = 트리거·ReportContacts·스크립트 엔티티·게임 모듈 `WantsCollisionEvents`. 이벤트는 `FPhysicsSystem::GetCollisionEvents`(물리 스텝 뒤 메인 스레드)에 쌓이고 `FGameWorld`가 물리·UpdateTransforms 뒤(`OnLateUpdate` 앞)에 전달 — Lua `OnCollisionBegin(other, info{Point,Normal,Impulse,Speed})`/`OnCollisionEnd(other)`/`OnTriggerEnter(other)`/`OnTriggerExit(other)`/`OnJointBreak(other, force)`, 게임 모듈 같은 이름. **Jolt 콜백에서 게임 코드를 부르지 않는다**. 트리거는 잠들지 않는 키네마틱 센서(`Trigger` 레이어, 레이캐스트 제외). 클라이언트는 복제 엔티티 이벤트를 내지 않는다. 관절 `Fixed/Hinge/Distance/BallJointComponent`(Target + Anchor)는 `FPhysicsSystem::SyncJoints`가 바디 동기화 뒤 만들고 설정/바디가 바뀌면 다시 만든다. Jolt 관절은 `FPhysicsWorld`만 소유하며 바디를 지우기 전에 지운다. 바디 쌍 충돌 끄기는 `FPhysicsWorld::DisableCollision`(그룹 ID = 바디 ID, 캐릭터 이동 질의도 따름). 래그돌은 모델 루트에 `RagdollComponent` — `FPhysicsSystem::EnableRagdoll/DisableRagdoll`이 캡슐 + SwingTwist 관절을 만들고 `FAnimationRuntime::bPhysicsPose`로 애니메이션을 멈춘 뒤 물리가 뼈 로컬 트랜스폼을 쓴다. 사망 연동은 `FGameWorld`가 모든 역할에서 복제된 체력 기준으로 하며 래그돌 자체는 비복제 로컬 연출

- 충돌 레이어(Phase 43, 유니티식): 프로젝트 설정 "충돌 레이어"(`FProjectSettings::Collision` = `FCollisionLayerSettings`, Core/Settings/CollisionSettings.h, `Config/Collision.json` — `Layers` 칸 순서 이름 + `DisabledPairs` 이름 쌍). 최대 16칸, 0 = "Default" 고정. 콜라이더(Box/Sphere/Capsule)와 `FCharacterMovementComponent`는 `Layer`에 **이름**을 저장하고(비었거나 없는 이름 = Default → 기존 씬 동작 동일, 없는 이름은 경고 한 번), 인스펙터는 리플렉션 `.StringOptions(공급자)` 콤보. Jolt 오브젝트 레이어 = 종류(정적/움직임/트리거, 하위 2비트) | 칸 << 2(`PhysicsWorld.cpp` `ObjectLayers::Make`) — 쌍 필터는 기존 종류 규칙 뒤에 행렬을 본다(트리거·캐릭터 이동 질의·캐릭터 내부 바디 모두). 행렬은 `FPhysicsSystem::Begin`이 복사해 `FPhysicsWorld::SetCollisionLayers`(플레이 시작에 고정). 새 바디/질의 코드는 `FPhysicsBodyDesc::CollisionLayer`/`FPhysicsCharacterDesc::CollisionLayer`(칸)를 채우고 질의 필터는 `FQueryLayerFilter`(트리거 제외 + 마스크). 레이캐스트 마스크: C++ `Raycast(..., LayerMask = FCollisionLayerSettings::AllLayersMask)`(`MakeMask`), Lua `Physics.Raycast(o, d, dist, {"Ground"} | "Ground")`(없는 이름은 Lua 오류). 레이어별 예외/트레이스 채널은 두지 않는다. 바꾸면 `CollisionLayerTests`도

- 플레이어 캐릭터/입력(Phase 21): 시점 회전은 원시 마우스(`WM_INPUT` → `FInput::GetLookDelta`, Lua `Input.GetLookDelta`), FPS식 커서 잠금은 `FWindow::SetCursorLocked`(포커스 잃으면 풀림, 런타임 ESC는 잠금 먼저 해제, Lua `Game.SetMouseLocked/IsMouseLocked` — 에디터는 미지원이라 우클릭 시점 등으로 대체). 시점 방향(언리얼 ControlRotation)은 소유 클라이언트가 `Net.SetControlRotation(yaw, pitch)` → 입력 커맨드와 함께 서버로 → 서버 스크립트 `entity:GetControlRotation()`(호스트/서버 소유 = 로컬 값). 플레이어별 카메라는 로컬 엔티티(`Scene.Create` + CameraComponent)에 `FCameraComponent::Priority`를 높게(주 카메라 중 큰 값이 이김). 캐릭터 캡슐은 `RigidBody.LockRotation`(Jolt 이동 자유도만) + `primitive:capsule`, 몸 방향은 자식 엔티티를 돌린다. **프리팹 자식은 자기에게도 `ReplicatedComponent`가 있어야 복제**된다(없으면 클라이언트는 프리팹 기본값). 클라이언트에서 `ReplicatedComponent` 소유자는 스크립트 `OnStart`보다 늦게 올 수 있으니 소유 판정은 확정될 때(매 프레임 확인) 한다. `FStaticMeshComponent`는 해석한 경로를 기억해 `MeshAsset/MaterialAsset`이 바뀌면(스크립트·복제) 다시 해석하고, Lua가 AssetFilter 문자열 프로퍼티를 쓰면 앱이 재해석한다. 샘플 `Scripts/PlayerCharacter.lua`(Both)가 기준 구현(테스트 `PlayerCharacter_MovesJumpsAndFaces`). **캐릭터를 따라가는 카메라는 `OnLateUpdate(dt)`에서** 놓는다(`FGameWorld::TickGameplay`가 물리·`UpdateTransforms` 뒤에 부름 — `OnUpdate`의 월드 위치는 물리 전 값이라 한 프레임 늦게 따라가 떨린다). 에디터 네트워크 플레이는 `FGameWorld::SetNetDriver`로 드라이버를 연결해야 원격 입력/RPC가 처리된다(`FPlayInEditorNet`이 Prepare/Stop에서). 입력 자동 검증: `--hold-keys W,Space`(A~Z, Space), 에디터가 띄우는 클라이언트에는 `--play-client-hold-keys W`. 자동 검증 실행은 Steam을 켜지 않는다(오버레이가 D3D 객체를 프로세스 끝까지 잡음 — 확인은 `--steam`, 항상 끄기 `--no-steam`)

- 캐릭터 이동/예측(Phase 22): 플레이어·AI 캐릭터는 `FCharacterMovementComponent`(Physics, Jolt CharacterVirtual — 트랜스폼 위치 = 캡슐 중심, 콜라이더/강체 불필요)를 쓰고 **스크립트는 이동을 직접 계산하지 않는다** — 조종하는 쪽(`FGameWorld::IsLocallyControlled`: 소유 플레이어가 로컬, 서버 소유는 서버)이 매 프레임 `entity:AddMovementInput(월드 방향)`/`entity:Jump()`. 실제 이동은 "무브" 단위 `FPhysicsSystem::SimulateCharacter`(같은 무브 → 같은 결과, 속도 규칙은 `CharacterMovementMath::ComputeVelocity` — 바꾸면 `CharacterMovementTests`도)를 서버·예측 클라이언트·Standalone이 공유한다. 멀티플레이 규칙은 `World/GameWorldCharacter.cpp` 머리 주석(무브 순번/겹쳐 보내기/서버 적용·ack/재조정/화면 오프셋 보정 흡수). 예측 캐릭터는 `FReplicationClient::SetTransformFilter(!IsPredicted)`로 스냅샷 보간에서 빠지므로 새 클라이언트 앱도 이 필터를 건다. 무브/ack 형식을 바꾸면 `NetProtocolVersion`. 몸 방향은 캐릭터 루트 yaw(`bFaceControlYaw` → `Net.SetControlRotation`의 yaw). 예측 옵션: 컴포넌트 `bClientPrediction` && 프로젝트 설정 네트워크 `bClientPrediction`(`FGameWorld::UsesClientPrediction`) — 끄면 무브만 보내고 스냅샷 보간으로 보여 준다. **넉백/발사**(2026-10-05, 2D 이동기와 같은 규칙 — 기준 `Physics/CharacterMovement.h` 컴포넌트 주석·`ComputeVelocity` 주석, 네트워크 `World/GameWorldCharacter.cpp` 머리 주석): Lua `entity:LaunchCharacter(속도[, 덮어쓰기 X, 덮어쓰기 Z])`(3D는 덮어쓰기 X = 수평 XY 묶음)·`AddKnockback(속도, 경직 초)`(XY 덮어쓰기, Z는 0이 아니면 덮어쓰기)·`IsStunned()`는 엔티티에 2D 이동기가 있으면 2D, 아니면 3D(`FPhysicsSystem::LaunchCharacter/AddKnockback/IsCharacterStunned/MergePendingLaunch`). 발사한 무브는 공중 규칙(점프·바닥 붙이기 없음 — 바닥이면 수직은 0부터 더함), 경직(상태 `FCharacterState::StunTimer`, ack에 실림) 동안 입력·점프·루트 모션 무시 + 수평 감속 `KnockbackDeceleration`(바닥·공중) — 수평만 발사하면 다음 무브에 다시 바닥이면 걷기 규칙(수평 = 입력)이라 밀려나는 효과는 AddKnockback. 무브 필드(`bLaunch/LaunchVelocity/덮어쓰기/StunSeconds`, 무브 플래그 4, 서버가 `MaxLaunchSpeed`·`MaxStunSeconds`로 자름)라 예측·재조정이 같은 결과, 서버가 원격 캐릭터에 준 넉백은 큐 첫 무브에 합쳐 ack로, 클라이언트가 남의 캐릭터에 건 것은 무시, 시간 정지 틱에는 다음 무브까지 남는다(`NetProtocolVersion` 15, `GameModuleApiVersion` 16). 바꾸면 `CharacterMath_LaunchAddsOrOverridesAndStun`·`Character_KnockbackTrajectoryDeterministic`(PhysicsTests)·`CharacterPrediction_KnockbackMatchesServer`·`TimeScale_KnockbackLuaApi3D`(ScriptingTests)

- 물리 예측(Phase 28, 언리얼 Predictive Interpolation식): 원격 클라이언트는 자기 예측 캐릭터 근처(`Network.PhysicsPredictionRadius`, 기본 300cm)나 닿은 루트 복제 동적 바디를 로컬에서 동적으로 시뮬레이션하고 서버 스냅샷으로 수렴시킨다(빠른 물체 300cm/s 이상은 닿을 때만). 규칙 기준은 `World/GameWorldPhysicsPrediction.cpp` 머리 주석(대상 선정, ack↔스냅샷 시각 맞추기, 기록 비교 보정 τ 0.15초/100cm 넘으면 스냅, 해제 블렌드, 재조정과의 관계). 새 클라이언트 앱은 `SetTransformFilter(!World.IsPredicted)`와 함께 `World.SetReplicationClient(&ReplicationClient)`를 BeginPlay 전에 연결한다(`IsPredicted`는 예측 바디도 참). 서버 코드·메시지는 그대로(속도는 스냅샷 차분), 끄기는 `Network.bPhysicsPrediction`. 캐릭터 재조정의 다시 적용 중에는 `SetCharactersPushBodies(false)`, 예측 바디는 재시뮬레이션하지 않고 `PoseBodiesForReplay`로 기록 위치에 잠시 둔다(전체 롤백 아님). 측정 `--net-physics-stats`, 바꾸면 `PhysicsPrediction_*` 테스트도. **2D**(`World/GameWorldPhysicsPrediction2D.cpp`)도 같은 규칙·상수·시계 — 2D 물리 단락
