# 렌더링 파이프라인 (렌더 그래프·PSO·렌더 스레드·성능·화면 품질·리소스)

> CLAUDE.md에서 옮긴 상세 규칙이다. 이 영역의 코드·에셋을 고치기 전에 읽는다. 규칙을 바꾸거나 더할 때는 이 문서(또는 관련 머리 주석)를 고치고 CLAUDE.md 요약 줄도 맞춘다.

- 렌더 그래프(Phase 47, `Renderer/RenderGraph/`): `FSceneRenderer::Render`마다 그래프 하나(등록 → 컴파일 → 실행). **새 패스는 그래프 패스로만 추가한다** — 하위 렌더러에 CPU 준비(`Prepare*`, 수집·상수 업로드)와 `Add*Pass(FRenderGraph&, ...)`(등록)를 나눠 두고, 람다는 `Context.CommandList`에 명령만 기록한다. **람다 안에서 `ResourceBarrier` 금지**(전이·UAV 배리어는 그래프가 패스 앞에 묶음, 예외: 같은 패스 안 같은 UAV 연속 디스패치 사이 `FRGContext::UavBarrier`). 패스는 GPU가 읽고 쓰는 모든 리소스·서브리소스를 `Read/Write(참조, ERGAccess, 범위)`로 선언하고, **셰이더가 읽지 않아도 루트에 묶는 표·루트 SRV의 리소스도 선언한다**(디버그 레이어가 그리기 때 상태 검사). 렌더러 소유 리소스는 `Import`(평소 상태 = 시작·끝 상태, 색 `ImportColor`=SrvPixel, 깊이 `ImportDepth`=DepthWrite) 또는 상태를 직접 추적하던 것은 `ImportTracked(&State)`, 프레임 안 중간 버퍼는 `CreateTexture`(크기·형식 키 풀링 — 직접 만들지 않는다). 전체를 덮어쓰는 쓰기는 `bOverwrite`(컬링 의존 끊김), 외부에 쓰지 않는 부수 효과 패스(리드백·통계)는 `NeverCull()`. 렌더 타깃은 `FD3D12RenderTarget::Bind`(Begin/End는 그래프 밖 오버레이용), GPU 구간은 `.Timer(ERenderTimer)`. 람다는 비동기 포크 때문에 등록 순서와 다른 CPU 순서로 불릴 수 있으므로 다른 람다가 만든 CPU 데이터에 기대지 않고 지역 변수는 값으로 캡처한다. 계산 셰이더만 쓰는 패스는 `ERGQueue::AsyncCompute` 후보(계산 큐 합법 상태 SrvNonPixel/Uav/Copy*만 선언) — `r.RenderGraph.AsyncCompute` 기본 0(Phase 47 측정: 제출 비용 > 겹침 이득), 새 계산 패스를 넣으면 `--async-compute`로 다시 잰다. 컴파일 규칙(컬링·읽기 합치기·서브리소스·포크/조인·묶음 합치기·수명)은 `RenderGraphCompiler.h` 머리 주석이 기준이고 바꾸면 `RenderGraphTests`도. 확인: `r.RenderGraph.Dump`(로그), 통계 창 "렌더 그래프", `--cvar r.RenderGraph.Cull=0`. 그래프 밖 수동 배리어는 업로드(지형 부분 업로드·캡처 업로드·업로드 큐)와 스왑체인/스크린샷, 에디터 오버레이 Begin/End만. 메모리 별칭(placed resource)은 2차 — 수명은 이미 계산됨

- PSO 캐시(Phase 48): PSO는 `FD3D12PipelineState::InitGraphics/InitCompute`로만, 루트 시그니처는 `FD3D12RootSignature`로만 만든다(`Device->Create*PipelineState`/`CreateRootSignature` 직접 호출은 캐시·워밍에서 빠짐). 키 = PSO 설명 필드 + 루트 시그니처 블롭 해시 + 바이트코드 해시(`D3D12PipelineRecipe.h`), 형식을 바꾸면 `FRecipeFile::Version`/`FLibraryHeader::Version`. 저장 `<Saved>/ShaderCache/`(드라이버 캐시 `PipelineLibrary.bin` = 머리 + 라이브러리 블롭 + 저장 키 목록 — **목록에 있는 키만 `Load*Pipeline`**(없는 이름 Load는 디버그 레이어 경고 971) + 사용자 레시피 `PipelineRecipes.epso`), 프로젝트 레시피 `Config/PipelineRecipes.epso`(`--record-pso`, 패키지 포함 — 패키징 직전 기록은 후속). 끄기 `--no-pso-cache`/`--no-pso-warm`, 로그 `[PSO 캐시]`, 테스트 `PipelineCache_*`. **워밍 스레드는 드라이버 캐시(파이프라인 라이브러리)를 읽지 않고 항상 Create**한다 — 작업 스레드의 라이브러리 Load와 섞으면 화면이 실행마다 달라졌다(2026-10-04, 드라이버 내부 원인 미상). 라이브러리 Load는 요청 스레드만. **드라이버 캐시(파이프라인 라이브러리)는 기본 끔**(`--pso-library`로 켬, 머리 주석 (c)) — 2026-10-05 재현: 라이브러리에서 Load한 PSO가 틀리게 그렸다(릿 스프라이트 PSO가 그림자를 읽지 않아 Tests/Tilemap2D 2D 그림자가 통째로 빠짐 — Release ↔ Debug 교대에서 요청은 Load·워밍은 다른 레시피를 Create하던 실행, 20회 중 5회), 그 PSO(또는 드물게 워밍 실행에서, 조건 미상)가 저장된 라이브러리 파일은 이후 Load만 하는 실행마다 같은 틀린 화면이었다(Materials·Decals·Terrain도). 워밍·요청 Create한 PSO는 모든 실행에서 맞았고 워밍이 레시피를 전부 만들어 시작 시간 차이도 없다(Tilemap2D 30프레임 벽시계: 기본 2.4s / 라이브러리 2.6s / 캐시 끔 2.7s). 켜면 드라이버 PSO 작업을 한 번에 하나(`FDriverScope`, 요청 우선)로 해 동시 Load는 막지만 저장 파일 문제는 남는다(형식 3 — 이전 파일 버림). PSO 캐시를 바꾸면 Tests/Materials·Decals·Terrain을 캐시를 켠 채 4회 연속 실행해 MD5가 모두 같고 `--no-pso-cache`와 같은지 확인한다 **PSO 지연 생성(2026-10-05, 2D 시작 시간)**: `FD3D12PipelineState::FDeferredCreationScope` 안의 `Init*`은 설명 사본(셰이더 바이트코드·입력 레이아웃·루트 시그니처 참조)만 기억하고 처음 `Get()`할 때 만든다(어느 스레드든 — 렌더 스레드 기록 중 첫 사용, 실패는 Fatal). `FSceneRenderer::Init` 전체와 런타임 UI/디버그 선 초기화가 범위 안 — 쓰지 않는 패스의 PSO(2D 게임의 3D 메시 변형·지형·물·구름·블룸 등)는 만들지 않고 요청·레시피에도 실제로 그린 PSO만 남는다(Crypt2D 132 → 18~21개, Hub 133 → 52개). 범위 밖(셰이더 다시 로드·그래프 머티리얼 변형·에디터 오버레이)은 즉시 생성(핫 리로드 실패 시 기존 유지가 즉시 판정에 기댐). **PSO 존재 확인은 `Get() != nullptr` 대신 `IsInitialized()`**(Get은 만든다). 비교 `--no-deferred-pso`. 워밍 순서 = 최근에 쓴 레시피 먼저(`LastUsedRun`), 요청한 키가 워밍 줄에 있지만 아직 시작 전이면 요청 스레드가 가져가 바로 만든다(`WarmTaken`, 시작했으면 기다림). **시작 시간 측정은 드라이버 셰이더 캐시를 감안**한다: NVIDIA 드라이버 캐시는 실행 파일 경로·내용별이고 같은 exe를 약 3번 실행해야 채워진다(그 전 2~3번째 실행도 느림) — 첫 실행(패키지 설치 직후)을 재현하려면 exe를 새 이름으로 복사해 `<Saved>/ShaderCache`를 지우고 잰다, 기준 로그 `[시작] 첫 프레임 표시 완료`(런타임, 첫 프레임 기록·Present 끝 — 프로세스 시작 시각과의 차). Crypt2D(2026-10-05, Release): 첫 실행 7.4 → 1.3~1.5s(프로젝트 레시피 포함, 없으면 1.8s), 2~3번째 4.3~4.6 → 1.15s, 드라이버 캐시 뒤 1.25 → 1.14s / Sample Hub: 첫 실행 8.8 → 5.2s, 2~3번째 5.8~6.2 → 2.3~2.6s, 뒤 2.36 → 2.29s. 2D 프로젝트는 `--record-pso`로 자동 검증 씬을 돌려 `Config/PipelineRecipes.epso`를 커밋한다(Crypt2D 21개 291KB — 렌더러/셰이더를 바꾸면 지우고 다시 기록)

- 렌더 스레드(2026-10-04, `r.RenderThread` 기본 1(사용자 요청 — 끄기 `--no-render-thread`), 런타임만 — 규칙 기준은 `Renderer/RenderThread.h` 머리 주석): 1단계 = **씬을 읽는 것은 게임 스레드, 명령 기록·제출만 렌더 스레드**. `FSceneRenderer::Render` = `BeginRender`(게임 스레드: 수집·팔레트·묶음·업로드·RT Prepare·파티클 수집/입자 업로드 + 그래프 패스 등록) + `FinishRender`(그래프 컴파일·실행 + 통계). 런타임 `OnRender`는 직전 렌더 작업 `WaitIdle` → BeginFrame → BeginRender → 오버레이 입력 사본(디버그 선 목록·UI 그리기 목록 + `FUIRenderer::PrepareTextures`·카메라·출력·스크린샷 경로) → `FRenderThread::Kick`(FinishRender → 디버그 선·UI 기록 → EndFrame/Present); 0이면 같은 작업을 그 자리에서. **그래프 패스 람다는 씬(ECS)·게임 전역(FDebugDraw, UI 글꼴, 앱 카메라)을 읽지 않는다** — 값 캡처 + 렌더러 소유 상태만(새 패스도). 씬이 필요한 그리기는 등록 때 준비해 값으로 넘긴다(예: `FParticleRenderer::PrepareDraws`/`RecordDraws`), GPU 리소스를 가진 컴포넌트 상태는 shared_ptr로 람다가 붙잡는다(GPU 파티클 풀). 렌더 스레드와 공유하는 상태를 게임 스레드가 **바꾸기 직전** `RenderThreadSync::WaitForRenderThread()`(Core, 언리얼 FlushRenderingCommands): `FResourceManager` 변경 함수 전부(경로 캐시 적중은 대기 없음 — **새 변경 함수도 첫 줄에**), 콘솔 변수 값 변경(같은 값이면 대기 없음). 앱이 직접 `WaitIdle`: 씬 로드/맵 전환/세션 전환, 창 크기·모드·VSync, 열린 콘솔, 종료, HDR 전환. 렌더 스레드에서 리소스 관리자·CVar를 바꾸면 경고 한 번(`[렌더 스레드] … 게임 스레드 소유 상태`). 기록 중 `FFrameTime`은 Kick이 넘긴 그 프레임 값(`FFrameTime::FScopedOverride`, 스레드별), `FD3D12RHI::DeferRelease/DeferFreeDescriptor`는 잠금(아무 스레드), 게임 스레드는 백버퍼 크기만 `GetBackBufferWidth/Height`로 읽는다(현재 백버퍼 RTV는 렌더 스레드 Present 중 바뀜), `FParallel::ParallelFor`는 두 스레드가 동시에 부르면 늦게 온 쪽이 순차. 검증: `--fixed-delta` 화면이 0/1 비트 동일(Stress·Hub·Campfire·Forest·PixelArt·GI·Terrain·Materials·Decals·AreaLights·맵 전환 + 리소스 수거, Stress는 master와도 동일), 측정 종료 로그 `[성능] 렌더 스레드`(렌더 작업·게임 스레드 대기 + CPU 구간: 게임 스레드(BeginFrame 펜스 대기 포함)·기록·제출). 이득(2026-10-04 ScaleBench, 측정 중 다른 트랙 GPU 경합으로 GPU 한계라 프레임 시간은 차이 없음 — CPU 한계 추정 = 게임 스레드에서 BeginFrame 대기를 뺀 값): 500유닛 3.9 → 2.6ms, 1000 6.5 → 5.7ms, 2000 12.8 → 12.3ms. 옮길 수 있는 몫이 기록 0.65 + 제출 0.7ms뿐이고 렌더 스레드 기록은 게임 스레드 병렬 루프와 코어·대역폭을 다퉈 약 2배 느려진다 → 큰 이득은 2단계(수집 이동). 에디터는 단일 스레드 유지(ImGui·패널·미리보기 렌더러가 프레임 안에서 씬과 렌더러를 오감). 2단계(수집을 렌더 스레드로)는 트랜스폼·스킨 뼈 월드 행렬의 프레임 끝 불변 사본(프록시)이 필요 — 지금은 수집 자체가 추출이라 게임 스레드에 있다

- 리소스 수거(Phase 37): 경로 캐시 리소스(LoadTexture/LoadMaterial/모델/파티클)는 루트 도달성 표시 → `Destroy*` 지연 해제 + 캐시 제거(규칙은 `Renderer/ResourceCollector.h` 머리 주석, 순수 식 `ResourceGc::Compute` — 바꾸면 `ResourceCollector_*` 테스트도). `Create*`로 직접 만든 리소스는 만든 쪽 소유라 수거하지 않는다. **씬 밖에서 경로 핸들을 오래 드는 새 코드(렌더러 캐시, 편집기, 앱)는 `FResourceManager::AddRootProvider`로 루트를 등록**하고(Shutdown에서 `RemoveRootProvider`), 새 씬 컨테이너(미리보기 등)는 `FResourceRoots::AddScene`. 수거는 매 프레임이 아니라 `RequestGarbageCollection`(2틱 지연, 앱은 프레임마다 `Resources.Tick()`) — 맵 전환·서브 씬 내림·에디터 씬 열기/플레이 정지·썸네일 대기열 비움이 요청한다. 끄기 `r.ResourceAutoCollect 0`, 수동 `r.CollectResources`, 통계 `stat memory`/`r.ResourceStats`/통계 창(VRAM = `FD3D12Device::QueryVideoMemory`). 로그 `[리소스 수거]`

- 비동기 업로드(Phase 37): 정적 버퍼/텍스처 초기 데이터는 `FD3D12UploadQueue`(복사 큐 + 64MB 링, 규칙은 `D3D12UploadQueue.h` 머리 주석)로 보낸다 — 대상은 COMMON으로 만들고 텍스처는 RHI BeginFrame이 COMMON → PIXEL_SHADER_RESOURCE로 전이(`GetFinalizedFence`), 복사 큐 명령 리스트에 다른 상태 전이를 넣지 않는다. 렌더 패스가 메시를 수집할 때는 `FStaticMesh::IsReady`를 확인하고, 텍스처는 `ResolveTexture`/머티리얼 테이블(준비 전에는 기본 텍스처)로만 읽는다. 새 생성 코드는 `FResourceManager`의 비동기 경로(`PendingUploads`)를 거친다. 로딩 방식 `r.AsyncLoading`(-1 자동 = 대화형 비동기 / 자동 검증은 비동기 + 프레임마다 비우기, 0 동기, 1 비동기, 2 비우기, 별칭 `--sync-loading`/`--async-loading`) — 앱은 `Resources.EnableAsyncLoading(IsAutomationRun())`, 테스트·도구는 부르지 않음(동기). 작업 스레드(`Core/Jobs/FJobQueue`)는 파일 읽기·디코드·압축·파싱만, GPU·ECS·리소스 관리자는 완료 콜백(메인). 결과를 고정 저장하는 코드(썸네일 등)는 `HasPendingLoads()`면 다음 프레임에 다시. 끊김 측정 `--log-hitches [ms]`
