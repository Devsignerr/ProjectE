# 네트워크·복제

> CLAUDE.md에서 옮긴 상세 규칙이다. 이 영역의 코드·에셋을 고치기 전에 읽는다. 규칙을 바꾸거나 더할 때는 이 문서(또는 관련 머리 주석)를 고치고 CLAUDE.md 요약 줄도 맞춘다.

- 네트워크(Phase 17, GameNetworkingSockets): GNS 헤더는 Network 모듈 .cpp에서만 포함하고 나머지는 `INetTransport`만 쓴다. 테스트는 `FLoopbackTransport`(소켓 없음), 실제 소켓 테스트는 포트를 범위에서 찾는다(GNS는 포트 0 불가). 메시지 형식/필드를 바꾸면 `NetProtocolVersion`을 올린다(다르면 접속 거부). 핸드셰이크는 프로토콜·엔진 버전·프로젝트·씬이 같아야 통과. 앱 인자: `--host [--port N]`(리슨 서버), `--connect ip:port`(클라이언트), `--join-lan`(LAN 첫 세션), 전용 서버 `--port`. 인자가 없으면 Standalone. LAN 방 목록은 `FLanDiscovery`(UDP 7778, 호스트가 응답). 에디터 네트워크 플레이는 `FPlayInEditorNet`(네트워크 패널, 인자 `--play --play-net listen|dedicated --play-clients N`): 편집 씬을 `Saved/PlayInEditor/PIE.escene`으로 저장하고 에디터 플레이 씬도 그 JSON에서 만든다(복제 금지 — 정적 NetId 일치). 정지하면 자식 프로세스(서버/클라이언트 창)를 닫는다. 디버그: `--net-lag <ms> --net-loss <%>`(보내는 쪽 지연/손실), 네트워크 패널 통계. **입장 전 메시지**: 서버는 Welcome(신뢰) 직후 비신뢰(스냅샷·ack)를 보내므로 손실·지연에서 Welcome 재전송 중 비신뢰가 먼저 올 수 있다 — 클라이언트 `Connecting` 상태는 Welcome/Reject 외 게임 메시지(종류 ≥ GameBase)를 버리고(`GetIgnoredPreJoinMessages`) 그 밖의 것만 "프로토콜 오류: 알 수 없는 응답 (첫 바이트, 크기)"(2026-10-05 Verify `--net-lag 100 --net-loss 5` 입장 실패 원인). 신뢰 게임 메시지는 신뢰 순서상 Welcome 뒤라 잃지 않는다. 손실·지연·재정렬 단위 테스트는 `FLoopbackTransport::SetSimulation`(+ `SetSimulationSeed`/`SetPollIntervalMs` — 시간 = 받는 쪽 Poll 수, 비신뢰 손실·흔들림 재정렬, 신뢰 무손실 + 재전송 지연 + 순서 보장, 결정적), 예 `NetDriver_JoinUnderLossLagAndReorder`(시드 200개). 멀티플레이 Verify 서버는 틱 수가 아니라 `--exit-when-empty 30 --exit-min-players <Clients>`(전용 서버 자동 검증 인자 — 그 수만큼 입장한 뒤 모두 나가면 30틱 뒤 정상 종료, `--exit-after`는 `Frames + 60 × TimeoutSeconds` 안전 상한)로 끝나므로 클라이언트 시작(디버그 레이어·PSO 컴파일 5~40초)이 늦어도 기본 `-Frames 150`으로 입장한다(2026-10-05 수정 — 예전 `-Frames 600` 우회 불필요). GNS 트랜스포트 `Close`는 연결이 있었으면 시뮬레이션 지연·손실(`--net-lag/--net-loss`)을 잠시 끄고 닫기 신호를 보낸 뒤 100ms 기다려 해제한다 — 곧바로 `GameNetworkingSockets_Kill`하거나 닫기 신호가 지연 큐에 남거나 잃으면 서버에 나간 클라이언트가 연결 시간 초과까지 남았다. 멀티플레이 변경 후에는 `.\Scripts\Verify.ps1 -Multiplayer`(전용 서버 + 클라이언트 2, `-ExtraArgs "--net-lag 100 --net-loss 5"`로 불량 망)도 돌린다. 실제 소켓을 여는 단위 테스트(GNS/LAN UDP)는 `FTestRegistry::AllowRealSockets()`(환경 변수 `E_TEST_SOCKETS=1`)일 때만 돌고 기본은 건너뛴다 — 0.0.0.0 바인드가 exe 경로마다(워크트리마다) Windows 방화벽 확인 창을 띄우기 때문. 네트워크 코드를 고쳤으면 `.\Scripts\Build.ps1 -Test -SocketTests`로 돌리고, 새 실제 소켓 테스트도 같은 확인으로 감싼다. 서버 대기·LAN 방 알림 주소는 `NetBindPolicy`(Network/NetBindPolicy.h): 자동 검증 실행(`--exit-after`)과 그 실행이 띄운 자식 프로세스(`--net-local`)는 **루프백 전용**(GNS 127.0.0.1 대기, LAN 알림 안 함 — 방화벽 확인 창 없음), 사람이 실행한 `--host`/전용 서버/에디터 네트워크 플레이는 모든 주소(`--net-public`으로 강제). 새 앱은 세션을 열기 전에 `NetBindPolicy::Configure(IsAutomationRun())`, 새로 0.0.0.0에 소켓을 여는 코드는 `IsLoopbackOnly()`를 따른다(2026-10-04 사용자 보고: 워크트리 exe마다 방화벽 확인 창)

- 복제: `ReplicatedComponent`가 붙은 엔티티의 리플렉션 컴포넌트 값만 서버 → 클라이언트로 간다(`FReplicationServer`/`FReplicationClient`, 형식은 ReplicationServer.cpp 머리 주석). 복제하면 안 되는 타입은 `.NoReplicate()`(TF_NoReplicate), 프로퍼티는 `PF_NoReplicate`, 리소스 핸들은 자동 제외(클라이언트가 경로로 다시 해석). `PF_Transient`는 저장만 빼고 복제는 된다. 정적 NetId는 "같은 씬 파일 로드에서 `ReplicatedComponent`가 추가된 순서"(엔티티 인덱스 아님)에 기대므로 씬 로드 직후·게임 시작 전에 `Begin`한다. 세션 전환(Lua `Net.Host/Connect/Disconnect`)은 `FGameWorld::ConsumeSessionRequest`로 앱이 처리한다. 클라이언트(`--connect`)는 `FGameWorld::BeginPlay(Scene, EWorldRole::Client)` — 게임 로직(스크립트/게임 모듈) 없이 물리만 돌리고 복제 엔티티(NetId)의 동적 바디는 키네마틱(`SetKinematicOverride`)으로 복제 트랜스폼을 따른다. 트랜스폼은 생성 때만 신뢰 채널, 이후 비신뢰 스냅샷 + 클라이언트 보간(`FReplicationClient::Update`, 0.1초 지연)이므로 클라이언트에서 트랜스폼을 직접 쓰지 않는다. 플레이어: `.eproject` `"PlayerPrefab"` → `FNetPlayerSpawner`(이름 `PlayerStart` 엔티티 위치, `OwnerPlayerId`). 복제 메시지를 바꾸면 `NetProtocolVersion`을 올린다
