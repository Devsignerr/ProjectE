# 애니메이션 (그래프·몽타주·IK·노티파이·리타기팅·루트 모션·병렬 갱신)

> CLAUDE.md에서 옮긴 상세 규칙이다. 이 영역의 코드·에셋을 고치기 전에 읽는다. 규칙을 바꾸거나 더할 때는 이 문서(또는 관련 머리 주석)를 고치고 CLAUDE.md 요약 줄도 맞춘다.

- 애니메이션 그래프(Phase 27): 에셋 `.eanimgraph`(JSON, `FAnimGraphAsset`, 경로 캐시 `FAnimGraphLibrary`, `FFileSystem`으로 읽음) + 모델 루트의 `FAnimGraphComponent`(있으면 `FAnimationSystem`이 `Clip` 대신 그래프로 재생, `AnimationComponent`의 Speed/Playing은 유지). 상태 = 클립 또는 1D 블렌드 스페이스(정규화 시간 동기화), 전이 = 목록 순서대로 처음 맞는 것 하나(조건 AND / ExitTime / smoothstep 페이드), 회전 nlerp. 재생·노티파이 규칙(최종 가중치가 가장 큰 기여 하나에서만 판정)은 `Scene/AnimGraph.h` 머리 주석이 기준이고 바꾸면 `AnimGraphTests`도. 파라미터는 복제하지 않는다 — Lua `entity:SetAnimParam/GetAnimParam/GetAnimState`(조상 엔티티에서 불러도 자손 그래프로), C++ `FAnimationSystem::SetAnimParam`. `bUseCharacterMovement`면 `FGameWorld::UpdateCharacterAnimParams`(물리·UpdateTransforms 뒤, OnLateUpdate 전)가 Speed/VerticalSpeed/Grounded를 덮어쓴다(시뮬레이션하는 쪽은 이동 상태, 원격은 보간 위치 변화 0.1초 평활)

- 애니메이션 고급(Phase 42): `.eanimgraph` v3(2D 블렌드 `BlendParameterY`/`PositionY`, `Layers`, `Slots` — v1/v2 읽기 유지). 최종 포즈 순서 = 기본 레이어 → 추가 레이어(본 마스크, 로컬 공간) → 몽타주(슬롯) → IK(발 → 시선) → 노드 기록. 상태 머신을 다루는 새 코드는 `Asset.GetMachine(레이어)`(-1 = 기본). 레이어/몽타주 노티파이 규칙은 `Scene/AnimGraph.h` 머리 주석이 기준. 몽타주(`Scene/AnimMontage.h`, `FAnimationSystem::PlayMontage`, Lua `entity:PlayMontage` + `OnMontageEnded`)는 **로컬 전용**(멀티플레이는 Both 스크립트가 각자 재생). IK(`Scene/AnimIK.h`, `FFootIkComponent`/`FLookAtComponent`)는 모델 공간·균등 스케일 가정, 래그돌(`bPhysicsPose`) 중 꺼짐. **발 IK 바닥 탐색은 World**(`FGameWorld::UpdateFootIkProbes`, `UpdateCharacterAnimParams` 뒤, 기존 `Raycast`) — Scene → Physics 의존 금지. Fox.glb는 모델 공간 -X를 바라봄(LookAt `ForwardAxis` = [-1,0,0]). 식을 바꾸면 테스트도: 2D → `AnimGraph_BlendSpace2D*`, 레이어·마스크 → `AnimGraph_BoneMask*`/`Layer*`, 몽타주 → `AnimMontage_*`, IK → `AnimIK_*`. 편집기 자동 검증 인자 `--animgraph-layer <이름>`, `--animgraph-slots`

- 애니메이션 갱신 병렬/빈도 LOD(Stress 최적화): `FAnimationSystem::Update` = 준비(메인, 엔티티 순서 — 세트·그래프 해석, 래그돌, URO 판정, `ResolveClipChange`, IK 뼈 해석: **로그·라이브러리 접근은 여기만**) → 포즈 평가(`FParallel::ParallelFor`, 엔티티별 독립 — 자기 런타임·자기 노드 로컬 트랜스폼만 쓰고 다른 엔티티는 월드 행렬 읽기만, 노티파이/몽타주 이벤트는 런타임별 Pending 목록) → 마무리(메인, 엔티티 순서 — 루트 모션 수신자 콜백). 평가 단계에 새 코드를 넣을 때 로그·ECS 구조 변경·콜백·다른 엔티티 쓰기 금지(필요하면 준비/마무리로). URO 규칙은 `Scene/AnimUpdateRate.h` 머리 주석(화면 크기 = 반경 / 화면 세로 절반, 엇갈림 = (런타임 틱 + 엔티티 번호) % 간격, 건너뛴 시간은 다음 평가가 한 번에 진행 → 노티파이 유지, 카메라 없음·일시정지·루트 모션·래그돌은 매 프레임 — 바꾸면 `AnimUpdateRate_*`). CVar `a.ParallelEvaluate`(1), `a.URO`(1), `a.URO.FullRateScreenSize`(0.2), `a.URO.HalfRateScreenSize`(0.08), `a.URO.MaxInterval`(4), `a.URO.Radius`(100cm × 루트 스케일). `FScene::UpdateTransforms`는 루트 하위 트리 단위 병렬(부착 지연 목록은 루트 순서로 합침, 평가한 모델은 `OutWritten`으로 표시 틱 부분 갱신에 알린다). 게임 쪽 틱 구간 CPU는 `--perf-capture` 종료 로그 `[성능] 게임 틱`

- 노티파이/소켓: 모델별 편집 데이터는 원본 옆 `<모델>.emeta`(`FModelMetadata`, Scene 모듈 — 쿠킹 입력 아님, `.eimport`와 달리 고쳐도 재임포트 없음). `FModelResources::Metadata`로 공유되어 `FAnimationRuntime::Metadata`/`FModelComponent::Runtime`이 읽는다(편집기가 고치면 즉시 반영). 콘텐츠 브라우저는 `.eimport`/`.emeta`를 숨기고 모델과 함께 옮기기/복제/삭제한다(`GetModelSidecars`). 노티파이 판정 규칙은 `Scene/AnimNotify.h` 머리 주석이 기준이며 순수 함수 `AnimNotifyMath::Collect`를 바꾸면 `AnimNotifyTests`를 함께 고친다. 이벤트는 `FAnimationRuntime::PendingNotifies`(애니메이션 갱신마다 비우고 채움) → 게임 모듈 `IGameModule::OnAnimNotify`(`GameModuleApiVersion` 2) / Lua `OnAnimNotify_<이름>`, `OnAnimNotifyBegin_/Tick_(dt)/End_<이름>`. 소켓 부착은 `FSocketAttachmentComponent`(대상 모델 엔티티 + 소켓 이름): 부착 엔티티의 로컬 트랜스폼은 소켓 기준이고 계층 부모는 무시된다. 로컬↔월드를 변환하는 코드(기즈모, 물리, 스크립트)는 `Scene.GetTransform(Parent).WorldMatrix` 대신 **`FScene::GetParentWorldMatrix`**를 쓴다

- 애니메이션 그래프/시퀀서(Phase 35): `.eanimgraph` v2의 편집기 정보(`EditorPosition`/`Editor`)는 실행에 쓰지 않는다. 그래프 파일을 바꾸는 코드는 `FAnimGraphLibrary::Invalidate(경로)`를 불러 사용 중인 컴포넌트를 다시 묶게 한다(파라미터 유지). 편집 중 사본 재생은 `FAnimGraphRuntime::SetAsset` + `ResolvedGeneration`을 현재 세대로. 시퀀스(`.esequence`) 트랙 대상은 엔티티 이름 경로(재생 엔티티 하위 → 씬 전체), 카메라 컷은 대상 카메라 `bPrimary` + Priority(`CameraCutPriority`)로 하고 끝나면 그 두 값만 되돌린다. 시퀀스 파일을 바꾸는 코드는 `FSequenceLibrary::Invalidate(경로)`. 편집 씬에 미리보기 값을 쓰는 편집기는 `FAssetEditor::SwapScenePreview/EndScenePreview`를 구현하고, 씬을 직렬화하는 새 코드(저장/스냅샷/Undo 커밋)는 `FAssetEditorManager::SwapScenePreviews`로 감싸 원래 값이 저장되게 한다

- 리타기팅(Phase 52 사이드, `Scene/AnimRetarget.h` 머리 주석이 기준): 다른 스켈레톤 클립은 `FAnimationComponent::RetargetSources`(Content 기준 모델 경로, `;` 구분) 또는 클립 이름 `"<모델 경로>:<클립>"`(Clip/그래프 샘플/Play/PlayMontage)로 쓴다. 시스템이 소스 클립을 리타기팅해 자기 클립 뒤에 덧붙인 세트를 만든다(`Runtime.BaseSet` → `Set`, 별칭 `ClipAliases`, 노티파이는 소스 `.emeta` — `ClipNotifySources`). 클립 번호를 기억하는 새 코드는 세트가 바뀌면 이름으로 다시 찾는다. 본 매핑은 휴머노이드 리그 23뼈(자동 = 이름 규칙 + 계층, 수동 = 모델 `.emeta` `"Retarget"`, `FModelMetadata` 형식 2), 매핑을 바꾸는 코드는 `FAnimRetargetLibrary::Invalidate(모델 경로)`. 변환 식(모델 공간 바인드 보정 회전 + 정면/A·T 포즈 Align, Root/Hips 이동 × 키 비율)을 바꾸면 `AnimRetarget_*` 테스트도(실제 에셋 양방향 방향 비교 포함). 각도를 그대로 옮기므로 비율이 다른 체형(치비 → 사실형)의 과장된 동작은 그대로 보인다(버그 아님, 체인별 보정은 후속). 편집기 검증 `--open-asset <모델> --retarget-preview <소스 모델>[:<클립>]`

- 루트 모션(`Scene/AnimRootMotion.h` 머리 주석이 기준): `FAnimationComponent::RootMotionMode`(None/MontagesOnly/All, 이전 `RootMotion` bool = All, 번호는 끝에만 추가), `RootMotionBone`, `RootMotionRotation`. 추출·제자리화·섞기는 `RootMotionMath`만 쓰고 바꾸면 `RootMotion_*` 테스트도. 새 포즈 원천(레이어/몽타주 등)을 추가하면 그 샘플도 제자리화하고 가중치 × 루트 노드 마스크로 합성한다. 적용은 `FAnimationSystem::SetRootMotionReceiver`(Physics 등록)가 자신·조상의 `FCharacterMovementComponent`에 쌓고 `TickCharacters`가 `ConsumeRootMotion`으로 무브에 싣는다(입력 대신 루트 모션 속도, 캐릭터 회전 없음), 캐릭터가 아니면 엔티티 로컬 트랜스폼을 직접 움직인다. 멀티플레이는 시뮬레이션하는 쪽만 싣는다 — 소유 클라이언트가 예측해 무브로 보내고(`NetProtocolVersion` 11, 서버가 `MaxRootMotionSpeed`로 자름), 서버/AI는 서버 권한, 전용 서버는 애니메이션이 없어 루트 모션 없음
